# qtim — команда AI-субагентов под твой проект

Плагин для Claude Code, который **одной командой разворачивает в твоём проекте команду специализированных субагентов** — архитектор, разработчики, тестировщик, ревьюер и другие. Вместо одного ассистента-универсала ты получаешь команду с чётким разделением ролей, общим списком задач и контролем качества, которая ведёт задачу от проектирования до финального ревью.

Плагин подстраивается под стек: анализирует проект, задаёт несколько вопросов (первый — твоя роль: разработчик, PM/аналитик, дизайнер или их комбинация) и генерирует роли под твои фреймворки.

## Что это даёт

- **Разделение труда** — каждая роль отвечает за свой слой: БД, фронтенд, тесты, ревью, архитектура. Меньше «каши» в одной голове.
- **PM-конвейер** — `/qtim:feature` проводит хотелку через PRD → декомпозицию → оценку (S/M/L/XL с evidence из кода) → план; мелкая хотелка без развилок идёт fast-path'ом: один feature-brief с одним подтверждением. Артефакты версионируются в `docs/features/<slug>/`, декомпозицию и оценку дают профильные dev-роли в consult-режиме.
- **Дизайн-трек** — `/qtim:design` ведёт дизайн-проект от пустой папки: 2-3 радикально разных направления → токены → один кликабельный прототип (самодостаточный HTML, уходит заказчику файлом) → показ-циклы с версиями → экраны → дизайн-система по выбору (Figma или код) → handoff в разработку со статусом кода.
- **Продуктовая память** — `/qtim:product-onboard` собирает из кодовой базы карту разделов, модель акторов, словарь домена и реестр событий аналитики (плюс материалы ПМа из `docs/product-context/`, если есть) — intake и PRD опираются на факты, а не на пересказ.
- **Подстройка под стек** — команда генерируется под твой проект (Nuxt/Next/NestJS/Postgres/…), а не по generic-шаблону.
- **Автоподбор инструментов** — при настройке плагин предлагает skills и расширения, релевантные твоему стеку.
- **Встроенные дисциплины** — собственные скилы плагина: `qtim:debug-loop` (диагностика сложных багов: воспроизводящий сигнал до гипотез, регрессионный тест до фикса), `qtim:prototype` (быстрый одноразовый прототип вместо спора о том, как фича должна выглядеть), `qtim:brainstorm` (разбор задачи до проектирования: интерпретации, варианты, open questions), `qtim:grill` (стресс-тест плана интервью — по одному вопросу, с рекомендованным ответом), `qtim:minimal-diff` (объём решения: лестница «нужно ли вообще → нет ли уже в проекте → …» и зоны, где упрощать нельзя), `qtim:design-prototype` (дизайн-деливерабл на показ: polish-правило, версии показов, судьба кода) и `qtim:codex-consult` (протокол независимого second-opinion через Codex на гейтах). Доступны ролям в любом проекте с установленным плагином.
- **Качество из коробки** — встроенные гейты: тесты, код-ревью, проверка результата перед завершением.
- **Гибкие режимы** — от лёгкого (одна задача) до полного эпик-флоу с циклами «сделал → проверили → доработал».

## Кто в команде

До 9 ролей (генератор подберёт нужные под твой проект):

- **architect** — проектирует, пишет ADR, следит за границами модулей
- **db / front** — разработчики своих слоёв (миграции и API / UI и компоненты)
- **tester** — реальные прогоны в браузере, не только проверки в коде
- **reviewer** — финальный гейт качества (безопасность, производительность)
- **explorer** — быстрый поиск по репозиторию
- **product** — PM/аналитик: intake хотелок, PRD, декомпозиция, оценки, планы + UX-аудит
- **devops / auditor** — инфраструктура и проактивный security/perf-аудит
- **designer / proto / ds** — дизайн-трек: направления и токены / прототип и экраны / дизайн-система (Figma или код)

## Требования

Нужен **Claude Code с включённым Agent Teams** — это мультиагентный режим, на котором работает команда. Включается флагом в `settings.json` (глобально `~/.claude/settings.json` или в проекте `.claude/settings.json`):

```json
{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }
```

## Установка

```bash
/plugin marketplace add toiiia/qtim-agent-team
/plugin install qtim@qtim-agent-team
```

## Быстрый старт

1. Открой Claude Code в корне своего проекта.
2. Разверни команду под него:
   ```
   /qtim:setup
   ```
   Плагин разберёт стек, задаст несколько вопросов и создаст команду прямо в проекте.
3. Работай через команды:
   ```
   /qtim:product-onboard  # PM: один раз собрать продуктовую память из кода
   /qtim:feature          # PM/аналитик: хотелка → PRD → декомпозиция → оценка → план
   /qtim:team-up          # поднять полную команду — для крупной задачи
   /qtim:team-lazy        # лёгкий режим — роли по мере надобности
   /qtim:team-down        # свернуть команду
   ```

## Команды

| Команда | Когда использовать |
|---|---|
| `/qtim:setup` | В новом проекте — выбрать роль и развернуть команду под стек; в проекте с командой — дозаполнить состав новой ролью, не пересоздавая существующее |
| `/qtim:feature` | PM/аналитик: провести хотелку от идеи до плана — PRD, декомпозиция, оценка, handoff в реализацию |
| `/qtim:design` | Дизайнер: провести проект от пустой папки — направления, прототип с показами, экраны, дизайн-система, handoff |
| `/qtim:team-up` | Крупная задача/эпик с циклами «сделал → проверили → доработал» |
| `/qtim:team-lazy` | Быстрая или средняя задача без полного прогрева |
| `/qtim:team-down` | Остановить команду (незавершённый эпик сохранится и продолжится в новой сессии) |
| `/qtim:team-sync` | После обновления плагина — подтянуть изменения в собранную команду |
| `/qtim:team-retro` | После эпика — дистилляция уроков в память команды |
| `/qtim:onboard` | Глубокое наполнение памяти на существующей кодовой базе |
| `/qtim:product-onboard` | PM-дорожка: собрать продуктовую память из кода — разделы, акторы, словарь домена, события аналитики |
| `/qtim:doctor` | Диагностика: флаг Agent Teams, charter, агенты, настройки, codex; плюс подсказка, каких ролей не хватает под выросший проект |

## Обновление

Плагин обновляется через маркетплейс (`/plugin` → Manage marketplaces → update, или `claude plugin update qtim@qtim-agent-team`). После обновления зайди в проект с собранной командой и запусти `/qtim:team-sync` — он перенесёт изменения движка в сгенерированные файлы (charter, роли, настройки), не трогая твою проектную конкретику и память. Если команда собрана по старой версии, плагин сам подскажет об этом при старте сессии.

## Как это выглядит

```
Ты:       /qtim:team-up, затем — «добавь раздел избранного: БД, API и UI»
Команда:  architect проектирует → db делает миграцию → front пишет UI →
          tester прогоняет в браузере → reviewer даёт вердикт
Ты:       получаешь готовый результат, а не сырой процесс
```

PM/аналитик:

```
Ты:       /qtim:feature, «хотим избранное для товаров»
Команда:  intake-вопросы → PRD → dev-роли смотрят реальный код →
          декомпозиция → оценки S/M/L/XL с evidence → план по фазам
Ты:       подтверждаешь ключевые точки (мелкая хотелка — одну);
          на выходе docs/features/favorites/ и готовый handoff для /qtim:team-up
```

## Что появится в проекте

После `/qtim:setup` в твоём проекте появляются описание команды (`.claude/team-charter.md`), роли-субагенты под твой стек (`.claude/agents/`), базовая память (`memory/`) и настройки в двух файлах: коммитируемый `.claude/settings.json` — флаг Agent Teams, выбранные hooks и базовые deny-правила (защита `.env*`, `~/.ssh` и опасных команд `rm -rf`, `sudo`, `git push --force`), — и личный `.claude/settings.local.json` с разрешениями, накопленными по ходу работы. Так коллега после `git clone` получает и флаг, и защиту, а не пустой проект.

В `CLAUDE.md` setup дописывает строку импорта charter — благодаря ей описание команды приезжает каждой роли автоматически, а не остаётся ссылкой, по которой роль может не сходить. Доменные требования, привязанные к путям (миграции, клиентский код, серверные routes), можно вынести в `.claude/rules/`: их подмешивают тому, кто открыл соответствующий файл. Всё это setup добавляет, показав дифф, и ничего не переписывает.

Сам движок команд живёт в плагине — проект остаётся чистым.
