# Changelog

Версии соответствуют `version` в `plugins/qtim/.claude-plugin/plugin.json` (semver). Пометка «team-sync» у версии говорит, нужно ли в собранных проектах запускать `/qtim:team-sync` (реестр миграций — `plugins/qtim/reference/migrations.md`).

## 1.14.0 — 2026-08-31

> team-sync: рекомендуется — пере-скопирует обновлённый `screenshots-gate.sh` (фильтр self-check-снимков обобщён до конвенции `*-selfcheck-*`) в проекты, где гейт включён, и подтянет standalone-набор (новые `commands/design.md`, `reference/design-pipeline.md`, `skills/design-prototype/`, правка `skills/prototype/`). Остальное приезжает с плагином автоматически; дизайн-дорожка в существующий проект добавляется повторным `/qtim:setup`, не миграцией. Перечень — `reference/migrations.md`, запись «→ 1.14.0».

### Добавлено

- **Дизайн-трек** — плагин закрывает флоу дизайнера от пустой папки до прототипа, экранов и дизайн-системы. Вход — Q0=Designer в `/qtim:setup`: на пустой папке стек-детект пропускается, вместо стек-вопросов — блок Qd (тип продукта, платформа, аудитория показа, материалы), состав фиксированный: `designer` + `proto` + `ds` + `reviewer` + `tester` + `explorer`. Ключевые решения флоу куплены стресс-тестом плана тремя оппонентами: **вариантность принадлежит направлениям** (2-3 радикально разных статичных концепта), кликабельный прототип всегда один и в утверждённом направлении; **polish-правило** — визуальная законченность и реалистичный контент обязательны (это деливерабл, заказчик покупает направление глазами), инженерная надёжность на стадиях направлений/прототипа не требуется; **экраны → DS-экстракция**, не наоборот — компоненты извлекаются из готовых экранов, когда паттерн повторился, а библиотека до экранов — библиотека под несуществующий продукт; **DS-target (figma | код) решается на гейте стадии 4**, не в setup — до утверждённого направления вопрос не имеет честного ответа, токены до гейта живут в нейтральном формате (CSS-переменные + `tokens.json`, компилируется в обе цели); **handoff фиксирует статус кода** (`reference` — dev переписывает, `foundation` — код принимается базой и проходит полный dev-гейт) — классическая точка войны «прототип → прод» закрыта явной развилкой.
- **`/qtim:design`** — тонкая команда конвейера: стадии (intake → направления → токены + прототип с показ-циклом → утверждение + DS-гейт → экраны → DS-экстракция → handoff), checkpoints, fast-path для мелочи, resume. Показы, сбор фидбека и утверждение ведёт team-lead — у ролей нет диалога с пользователем (класс «роль не может исполнить предписанное» из уроков 1.12.0 учтён с порога). Контракты, переживающие сессию, — `reference/design-pipeline.md`; статусы, slug и resume-механика **не переопределяются** — ссылки на канон `feature-pipeline.md`.
- **Четыре шаблона ролей.** `designer-agent` (направления с словесной гипотезой каждого, дистилляция в токены с именами по роли, арт-дирекшн консистентности), `proto-agent` (один прототип, версия на каждый показ, правки только по пунктам фидбека; режим SCREENS с полными обязательствами — после DS-гейта), `ds-agent` (экстракция из повторившихся паттернов; ветка кода — скаффолд + тема + showcase, ветка figma — fail-soft с обязательной строкой `ds-channel:` в отчёте: неавторизованный figma-MCP для субагента невидим — замер CLI 2.1.246 в `runtime-compat.md`, отказ канала не должен выглядеть как успех), `reviewer-design-agent` (гейт до показа и на handoff; hardcode мимо токена — блокер; имя файла намеренно с префиксом `reviewer-` — так сгенерированный агент попадает под проверку строк схемы отчёта в `check_golden.py` без правки чекера). Хендоффы между ролями — только через утверждённые артефакты (концепт + токены → прототип → экраны): на словесном пересказе направления теряется ровно то, что нельзя специфицировать.
- **`qtim:design-prototype`** — скил дизайн-деливерабла: polish-правило, самодостаточность файла показа (открывается без сервера, уходит заказчику файлом), версии `v<N>.html` без перезаписи, итерация по полученному фидбеку, судьба кода (в прод не эволюционирует без явного `foundation`). Скил собственный, не адаптация: апстримы прототип-дисциплин описывают throwaway для дев-развилки, а здесь прототип — деливерабл; граница с `qtim:prototype` выписана в обоих SKILL.md с обеих сторон (урок границы brainstorm↔grill: граница, живущая только в порядке шагов одной роли, не держится).
- **Эталон `examples/greenfield-design/`** — вымышленный дизайн-проект glow, Q0=Designer на пустой папке: charter с секцией «Дизайн-конвейер», четыре дизайн-роли + адаптированный `testing-agent`, DS-target намеренно не решён — обе ветки `ds`/`proto` с пометкой «активируется гейтом» (демонстрация генерации greenfield до выбора цели). Golden — в той же задаче, что и шаблоны (инвариант 8); правил `.claude/rules/` нет намеренно: в пустой папке глобы `paths` мертвы.
- **`/qtim:doctor` п. 11** — новый сигнал: `DS-target: figma` в charter при недоступных figma-скилах → warn.
- **Замер CLI 2.1.246** в `reference/runtime-compat.md`: неавторизованный MCP-сервер для субагента невидим (тулы отсутствуют, а не падают с ошибкой), браузерные тулы приходят в основном наборе — на этом стоят fail-soft figma-ветки и self-check дизайн-ролей.

### Изменено

- **`screenshots-gate.sh`** — исключение self-check-снимков обобщено с префикса `front-selfcheck-` до конвенции `*-selfcheck-*` (`find ... ! -name`): покрывает дизайн-роли и любые будущие self-check-роли без повторных правок broadcast-критичного гейта; текст stderr обновлён. Без этого self-check дизайн-ролей ложно закрывал бы гейт тестера.
- **`check_placeholders.py`** — белый список: + `TOKENS_PATH`, `SHOWCASE_CMD` (nuxt-ветка `ds-agent`); список Phase 1 в `setup.md` синхронизирован. `{{DS_TARGET}}` плейсхолдером намеренно не заводился: ветвление figma/код генератор делает вырезанием стек-условных блоков (механика 4.2), плейсхолдер-переключатель в сгенерированный текст не попадает.
- **`validate.yml`** — JSON-шаг: + оба settings нового эталона (список манифестов поимённый — новый файл сам не подхватывается).
- **`setup.md`** — перечень команд шапки и перечень копирования 4.6 Standalone: + `design`; локализация handoff-шаблонов расширена на `design-pipeline.md`; Phase 1 — правило пустой папки; Phase 1b — строки дизайн-маппинга скилов (figma-скилы только fail-soft); Phase 4.1 — charter-секция «Дизайн-конвейер» (производная от reference); Phase 4.2 — особенности генерации дизайн-состава, включая отличное от dev безусловное ядро (polish-правило вместо loading/empty/error на стадиях направлений/прототипа).
- **`intake-protocol.md`** — развилка прототипов: в дизайн-конвейере прототип — деливерабл (`qtim:design-prototype`), не разрешение развилки.

## 1.13.0 — 2026-07-29

> team-sync: рекомендуется — подтянет в сгенерированные роли ссылки на новый скил `qtim:minimal-diff` (у `front` — секция «Объём решения» и строка чеклиста, у `architect` — абзац в шаге 1 режима DESIGN и строка смелла в REVIEW, у `db` — секция с акцентом на перенос правила в ограничение/индекс и строка чеклиста, у `reviewer` — подраздел «Объём решения» в шаге 2 как класс рекомендаций), доведёт то же до ролей без файла-шаблона, которые правят код (`devops`, impl-роль под нестандартный стек), и допишет практики в charter-таблицу, колонку «Mandatory practices» — вместе с `qtim:debug-loop` у `db`/`front`/`tester`, который в charter не попал ещё с 1.10.0. Без миграции роли работают по-прежнему: скил доступен в сессии, но никто его не вызывает — ссылок на него в сгенерированных файлах нет. Перечень — `reference/migrations.md`, запись «→ 1.13.0».

### Добавлено

- **`qtim:minimal-diff`** — дисциплина объёма решения: лестница из семи ступеней до написания кода (нужна ли функциональность вообще → есть ли уже в проекте → штатная библиотека → возможность платформы → уже установленная зависимость → одна строка → минимальная реализация), маркер осознанного упрощения в коде (`minimal-diff: <потолок> — <что делать, когда упрёмся>`) и явный список защищённых зон, обязательства в которых фиксируются целиком — их нельзя ни выбросить как спекулятивные, ни отложить маркером, хотя минимальный полноценный способ выполнить их лестница как раз и выбирает: валидация на границе доверия, обработка ошибок против потери данных, безопасность, база доступности, явно запрошенное пользователем. Производная адаптация [`ponytail`](https://github.com/DietrichGebert/ponytail) (MIT) — как `debug-loop`, `prototype` и `grill`: структура и часть правил заимствованы, текст написан заново под контракт команды и русский язык, а три механики оригинала не перенесены — формат вывода («код плюс три строки»), режимные уровни `lite/full/ultra` и право отказать требованию прямо в ответе. У ролей своя схема отчёта, а сужение согласованного объёма — не решение исполнителя: расхождение с задачей идёт в open questions и эскалацию team-lead'у. Граница с соседним скилом проведена в тексте: `qtim:prototype` отвечает на вопрос развилки и выбрасывается, `minimal-diff` определяет объём кода, который останется в main. **Отдельно стоит отметить новое обязательство исполнителя:** нетривиальная логика (ветвление, цикл, парсер, деньги, разграничение доступа) не считается готовой без одной минимальной проверки, реально падающей при поломке, — пишется штатным тест-раннером проекта и без разворачивания нового сьюта или инфраструктуры фикстур; полное покрытие и матрица сценариев остаются зоной `tester`.
- **У пересмотра состава команды появился момент, когда о нём спрашивают** — `/qtim:doctor` (п. 11) сопоставляет роли charter с фактами репозитория: есть CI-конфиги, а `devops` в составе нет; есть миграции, а impl-роли данных нет; есть публичная часть, а `product` нет; в монорепо несколько стеков, а impl-роль одна; и обратное — роль есть, слоя под неё в проекте нет. Вся категория — warn и только рекомендация: диагност контракт команды не переписывает, роли добавляет пользователь. Исполняется повторным `/qtim:setup`, у которого правило «дописывает, не пересоздаёт» расширено с PM/dev-дорожек на любую роль. Отдельную команду заводить не стали намеренно: состав фиксируется на старте, когда проект ещё не оброс инфраструктурой, и потом не пересматривается не из нежелания, а потому что негде — `doctor` таким местом уже является, а третья команда конкурировала бы с ним и с `setup` за одно и то же назначение.
- **`/qtim:team-retro` собирает маркеры упрощений** — `grep` по `minimal-diff:` за эпик, и маркер со сработавшим триггером (объёмы выросли, нагрузка пришла) заводится задачей, а не остаётся заметкой на будущее. Без жатвы маркер write-only: его смысл — чтобы потолок всплыл на ревью, а не инцидентом.
- **`qtim:debug-loop`, фаза 5** — перед правкой найти все места вызова функции и соседние пути через неё: фикс на одном пути, том что пришёл из репорта, оставляет остальные сломанными уже сейчас. Правило пришло из сверки с апстримом `minimal-diff` — там это pre-edit-шаг, а не следствие «чини в корне».
- **`THIRD_PARTY_NOTICES.md`** — copyright и permission notice апстримов всех четырёх скилов-адаптаций (`mattpocock/skills` для `debug-loop`/`prototype`/`grill`, `DietrichGebert/ponytail` для `minimal-diff`). Строка атрибуции в шапке `SKILL.md` — не то же самое, что notice, которого требует MIT при распространении; до этой версии его не было ни у одной из трёх прежних адаптаций. Требование записи закреплено в CLAUDE.md как контракт на будущие скилы.
- **`check_skill_refs.py` в CI** — `name:` во frontmatter скила обязан совпадать с каталогом, каждое упоминание `qtim:<name>` без ведущего слэша в `plugins/` и `examples/` обязано резолвиться в существующий скил или команду. Пробел, который вскрылся именно на этой правке: вызов скила стал строкой обязательного чеклиста роли, а опечатка в имени не ломала ни одну проверку — `check_links.py` смотрит markdown-ссылки, `check_golden.py` — только наличие инструмента `Skill`. Роль при этом молча не выполняла бы пункт.
- **`/qtim:setup` (4.1) задаёт содержимое колонки «Mandatory practices»** — гейты роли плюс вызовы собственных скилов из её шаблона. Раньше специфицировано было только имя колонки, поэтому свежесгенерированный charter мог остаться без практик, которые миграция требует от уже собранных проектов.
- **Роли `front` и `architect` вызывают лестницу на своих точках** — `front` перед реализацией нетривиальной задачи (типовые находки reviewer'а: абстракция под один вызов, локальная копия существующей fetch-логики, библиотека ради одной функции), `architect` при сравнении вариантов в DESIGN, где ступени «нужна ли сущность вообще» и «нет ли уже в проекте» часто снимают развилку до выбора. У `db` — и у любой impl-роли, сгенерированной из того же шаблона (`backend`, `analytics`) — акцент смещён на четвёртую ступень: правило, выраженное ограничением, индексом или триггером, дешевле той же проверки, размазанной по коду. Роль долго оставалась без дисциплины из осторожности — её работа плотнее всего соприкасается с зонами, где упрощать нельзя, — но зоны и лестница разведены явно: обязательства фиксируются целиком, лестница выбирает только способ их выполнить, и это записано в самой секции роли. Проверяет объём `reviewer` — подразделом чеклиста в классе рекомендаций: нарушения инварианта в «абстракции под один вызов» нет, поэтому вердикт такие находки не блокируют.

## 1.12.0 — 2026-07-27

> team-sync: рекомендуется — заменит в сгенерированных ролях блок «Persistent Agent Memory» на короткий «Память роли», переведёт указатели ролей с `reference/codex-consult.md` на скил `qtim:codex-consult` и **уберёт из charter абсолютный machine-specific путь к `reference/*`** (из-за него charter ломался при переносе проекта на другую машину; `/qtim:doctor` теперь предъявляет такой путь как признак charter'а до 1.12.0), пометит charter-секцию «PM-конвейер» производной сводкой, сверит списки скилов роли с charter, допишет `reviewer`'у выход из тупика «money-critical + недоступный codex» вместе со строкой `## adversary:` в схеме отчёта, а `tester`/`product`/`auditor` и charter — путь на случай невыданных `Task*`. Движок backward-tolerant: без миграции роли работают, но старый блок продолжает диктовать формат памяти, противоречащий рантаймовому, обещает `architect`/`reviewer` лимит больше фактического, а `tester` в режиме C остаётся без альтернативы `TaskCreate`. Отдельно sync допишет в `CLAUDE.md` проекта строку импорта charter (доставка контракта ролям вместо указателя) и предложит — не навязывая — правила по путям и блокирующий screenshots-gate. Перечень — `reference/migrations.md`, запись «→ 1.12.0».

### Добавлено

- **Charter доезжает до ролей сам** — `/qtim:setup` (4.5) пишет в `CLAUDE.md` проекта строку импорта `@.claude/team-charter.md`. Рантайм отдаёт роли [всю иерархию CLAUDE.md в стартовом контексте](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup), а импорт разворачивается в неё дословно — контракт команды приезжает роли без единого действия с её стороны. Раньше доставка держалась на инструкции «прочитай charter на спавне»: роль могла по указателю не сходить, и никакой признак этого не отличал бы её от сходившей. Проверено фактическим замером (CLI 2.1.220, `reference/runtime-compat.md`): маркер из импортированного файла присутствует в контексте роли, поднятой **без** инструментов чтения. Прежние инструкции оставлены: `CLAUDE.md` принадлежит пользователю и импорта может не содержать, а роль `explorer` (`subagent_type: Explore`) CLAUDE.md не получает по устройству рантайма.
- **`.claude/rules/` — доменные требования по путям** (setup 4.5a): требования к миграциям, клиентскому коду и серверным routes выносятся в правила с frontmatter `paths`, и рантайм подмешивает их **всякому, кто открыл совпавший файл** — исполнителю в момент правки, без обращения к charter. Тем же замером установлена граница механизма: правило поднимается только на `Read`; `cat` и `git diff` через `Bash` его не поднимают. Поэтому чеклист `reviewer` остался на месте — роль работает по диффу, и замена чеклиста правилами обнулила бы финальный гейт. Два независимых слоя вместо одного: правило ловит исполнителя на входе, чеклист — на выходе. Ролям `db`/`front`/`reviewer` добавлен абзац «файлы открывай через `Read`» — без него канал не работает.
- **Блокирующий screenshots-gate** — опция Q7 и готовый скрипт `templates/hooks/screenshots-gate.sh`: на `SubagentStop` роли-тестера гейт смотрит каталог скриншотов и, не найдя свежих снимков (`front-selfcheck-*` не в счёт), возвращает роль в работу через `exit 2`. Раньше требование «acceptance не закрывается без скриншотов» держалось только прозой промпта. По умолчанию **выключен**: это единственная часть плагина, которая останавливает работу, и живёт она в `.claude/settings.json` проекта, где выключается удалением одного блока. Дизайн продиктован замером: `exit 2` возвращает роль в работу, **подменяя ей задачу текстом из stderr** (зонд с заданием «ответь одним словом» вместо ответа стал разбираться с требованием гейта), поэтому гейт проверяет факт на диске, а не отчёт роли, пишет в stderr выполнимое действие и блокирует один раз за сессию — иначе роль, физически не способная его закрыть, не вышла бы из петли. У `tester` добавлен абзац: текст гейта — не новая задача, а задача без UI закрывается явной пометкой в отчёте.
- **CI ловит то, что раньше ловили люди на ревью** — два новых скрипта. `check_migrations.py`: правка `templates/**` или раздела «Phase 4: Generation» в `setup.md` без записи `## → <версия>` в реестре миграций роняет сборку — за прошлый релиз три таких пропуска дошли до пятого-шестого раунда ревью, потому что контракт держался на памяти автора. Триггер по setup.md считается по номерам изменённых строк, поэтому правки Discovery, вопросов и хендоффа проверку не будят; база сравнения, которая не резолвится, — явный fail, а не молчаливый зелёный (для этого в checkout `fetch-depth: 0`). `check_golden.py`: эталон проверяется семантически, а не только на отсутствие плейсхолдеров — обязательные секции и штамп версии charter, `name`/`model`/`tools`/`memory` во frontmatter ролей, `Skill` у ролей со скилами, `agent-memory/<role>/MEMORY.md`, строки `## codex-consult:` и `## adversary:` в схеме отчёта `reviewer` (именно как строки схемы: упоминание в прозе под ней проверку не закрывает). Заодно в JSON-шаг добавлен `settings.json` эталона, появившийся в этой же версии и в проверку не попавший.
- **Golden-эталон расширен с одной роли до полного dev-состава** — `architect`, `front`, `tester`, `reviewer` рядом с прежним `db`, плюс `agent-memory` для ролей с включённой памятью. Раньше эталона не было в том числе у `reviewer` — роли с самой ошибкоопасной схемой отчёта, где в этой же версии появилась строка `## adversary:`.
- **`reference/runtime-compat.md`, замеры CLI 2.1.220** — что доезжает до роли само (CLAUDE.md, `@`-импорт, правила с `paths` и без) и как это замерять маркерами; поведение `SubagentStop` с `exit 2`. ### Добавлено

Каталог `skills/` плагина — qtim впервые поставляет собственные скилы, а не только матчит чужие (Phase 1b setup). До сих пор шаблоны ролей могли ссылаться на внешние скилы только fail-soft («`brainstorming` … если доступен»): их наличие зависит от окружения конкретного пользователя, и mandatory-практика architect'а фактически была mandatory только там, где скил случайно установлен. Скилы из `plugins/qtim/skills/` приходят с плагином и доступны в любой сессии как `qtim:<skill>` — и team-lead'у, и субагентам через `Skill`; движковой orchestration-логики в них нет. Четыре дисциплины (`debug-loop`, `grill` — адаптации из [mattpocock/skills](https://github.com/mattpocock/skills), MIT; `prototype` — оттуда же; `brainstorm` — собственная выжимка дизайн-фазы intake-протокола):

- **`qtim:debug-loop`** — дисциплина диагностики нетривиальных багов и перф-регрессий: красный feedback loop до любых гипотез (без него к теориям не переходить), минимизация репро, 3-5 фальсифицируемых гипотез до проверки первой, инструментирование по одной переменной с тегами `[DEBUG-*]`, регрессионный тест до фикса, cleanup одним grep. Закрывает дыру баг-флоу: tester локализовал слой → TaskCreate → а дальше исполнитель вёл фикс без всякой дисциплины. Встроен: `db`/`front` — блок «Нетривиальный баг» (политику доступа «на глаз» без красного репро не переписывать), `tester` — подъём частоты воспроизведения плавающих багов (50 % дебажится, 1 % — нет).
- **`qtim:prototype`** — throwaway-прототип для разрешения дизайн-развилки: терминальный мини-скрипт для логики/стейт-машины или несколько радикально разных UI-вариантов на одном роуте (`?variant=`). Вердикт — в артефакт, породивший вопрос; в main живёт только решение, прототип в production не эволюционирует. Встроен в дизайн-фазу intake-протокола и DESIGN architect'а: развилку «как должно выглядеть/вести себя» дешевле разрешить реакцией на конкретное, чем выбором между абзацами.
- **`qtim:brainstorm`** — разбор до проектирования: минимум две интерпретации задачи, факты из окружения — сам (правило «факт vs решение»), 2-3 жизнеспособных варианта с трейд-оффами (включая минимальный; вариант-чучело — анти-паттерн), open questions отдельно от помеченных предположений. Заменяет fail-soft зависимость architect'а от внешнего `brainstorming`: «обязателен до ADR» теперь действительно обязателен в любом окружении.

Liveness по-прежнему сессионный, но эпик больше не теряется.
- **Комплект готовых Workflow-скриптов** в `plugins/qtim/workflows/` (запуск по `scriptPath`, opt-in обязателен): `ensemble-review.mjs` (линзы → скептик-верификация → вердикт), `access-audit.mjs` (fan-out по сущностям → карта видимости + щели), `flaky-hunt.mjs` (loop-until-trace с бюджет-guard'ом). Named workflows из orchestration-patterns теперь поставляются, а не только описываются; в standalone копируются в `.claude/workflows/`.
- **`/qtim:onboard`** — глубокое наполнение памяти существующего проекта: план → подтверждение объёма → fan-out исследователей по подсистемам (read-only) → синтез карты/инвариантов/конвенций в `memory/` с прецедентами file:line.
- **`/qtim:doctor`** — read-only диагностика с фиксами: флаг Agent Teams, версия/штамп charter, целостность агентов (frontmatter, tools, неподставленные плейсхолдеры), settings, память, codex, reference-пути.
- **`examples/nuxt-supabase/`** — golden-референс сгенерированного (charter, роль db, settings, baseline-память) как живая документация и эталон для сверки при правках шаблонов; CI проверяет отсутствие плейсхолдеров в examples.
- CI: синтакс-проверка Workflow-скриптов (`check_workflows.mjs` — AsyncFunction-парсинг, как исполняет движок; обычный `node --check` даёт ложный fail на легальном top-level return); обратная проверка examples в `check_placeholders.py`.
