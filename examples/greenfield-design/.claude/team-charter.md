# Team Charter — glow

Версия 1.0 · 2026-08-31 · generated-by: qtim v1.14.0 · mode: plugin-linked

## Назначение

glow — дизайн-проект нового сервиса подписки на живые растения: лендинг + личный кабинет
подписчика. Старт с пустой папки: сначала направления и кликабельный прототип на показы
заказчику, затем экраны и — при заказе — дизайн-система. Кода продукта здесь пока нет;
деливераблы живут в `docs/design/<slug>/`.

## Стек (фиксированный)

- **Прототип-фаза:** самодостаточные HTML-файлы (инлайн-стили, без сборки) — открываются без
  сервера, уходят заказчику файлом. Токены — CSS-переменные + `tokens.json` (нейтральный
  формат: компилируется и в Figma variables, и в тему кода).
- **Цель дизайн-системы** (`figma` | `код`, типовой кодовый вариант — Nuxt) — см. строку
  `DS-target:` в секции «Дизайн-конвейер»: она единственный носитель этого решения, конвейер
  обновляет её на гейте стадии 4. Команды кодового проекта появятся после скаффолда и будут
  вписаны в design-brief.
- **Показ:** аудитория — заказчик и продакт; фидбек возвращается через владельца проекта,
  фиксируется в `docs/design/<slug>/feedback-N.md`.
- **Материалы:** бриф и референсы заказчика — `docs/design/<slug>/design-brief.md`.

## Intake-режим

Автопилот с асимметрией: направления и показы совместно с пользователем (checkpoint на каждом
показе), вёрстка автономно, вопросы — на необратимых развилках (DS-target, статус кода на
handoff). Механика — `intake-protocol.md` плагина; конвейер — `/qtim:design`.

## Доменные инварианты (нерушимы)

1. Вниз по конвейеру едут только **утверждённые** артефакты: направление без показа не
   становится прототипом, прототип без утверждения — экранами.
2. Вариантность принадлежит направлениям; кликабельный прототип всегда один.
3. Артефакт показа самодостаточен: открывается без сервера, уходит файлом.
4. Значения — токенами; со стадии токенов hardcode мимо токена — блокер.
5. Компоненты DS извлекаются из повторившихся паттернов готовых экранов, не проектируются
   заранее.
6. Прототип не эволюционирует в прод без явного решения `foundation` на handoff-гейте.

## Codex second-opinion

Gate-точки: reviewer на handoff-гейте и на foundation-коде. Протокол — скил
`qtim:codex-consult`, роль вызывает его через `Skill` в момент гейта (advisory: инвариант
проекта > совет codex; read-only; fail-soft; вкусовые советы по дизайну — не findings).
Foundation-код — второй независимый оппонент, поднимает team-lead.

## Правила работы

- Коммуникация — `SendMessage`; задачи — `TaskCreate`/`TaskUpdate` с `owner`; общий список
  один. Нет `Task*` у роли (ни в наборе, ни через `ToolSearch`) — состав задачи team-lead'у
  через `SendMessage`, список ведёт он.
- Инструменты поиска: `Grep`/`Glob` заявлены в `tools:` ролей; если рантайм их не выдал —
  поиск и листинг через `Bash` (`rg`, `grep -rn`, `ls`).
- Показы, сбор фидбека и утверждение ведёт team-lead — роли готовят деливераблы и итерируют
  по полученному фидбеку.
- Figma-канал — fail-soft: неавторизованный figma-MCP для роли невидим; отказ канала — явной
  строкой `ds-channel:` в отчёте, не молчанием.
- Universal skills (проверены на доступность): `using-superpowers`.
- Канон рантайма (упразднённость `TeamCreate`/`team_name`) — см. `/qtim:team-up`, здесь не
  дублируется.
- Anti-patterns: спавн дублей вместо `SendMessage`; отчёт процессом вместо результата; правки
  чужой зоны (см. do-not-touch); показ, который ведёт роль; версия поверх предыдущей.

## Дизайн-конвейер

Производная сводка от `design-pipeline.md` плагина — канон там, при расхождении верен он.

- Артефакты `docs/design/<slug>/`: `design-brief.md` (вводные, аудитория показа, выбранное
  направление, DS-target, статус кода) · `directions/<name>.html` · `prototype/v<N>.html` ·
  `feedback-<N>.md` · `screens/` · `## Handoff` в brief. Статусы — как у PM-конвейера:
  Draft → Approved (пользователь на показе) → In Development → Done.
- Правило направлений: 2-3 статичных радикально разных концепта → показ → выбор; кликабельный
  прототип один, в выбранном направлении.
- Polish-правило (канон — скил `qtim:design-prototype`): визуальная законченность и
  реалистичный контент обязательны; типы/тесты/обработка ошибок на стадиях направлений и
  прототипа не требуются. Полные обязательства качества — со стадии экранов.
- `DS-target: решается на гейте стадии 4`; до него токены в нейтральном формате. Figma-ветка
  fail-soft со строкой `ds-channel:`.
- Порядок: экраны → DS-экстракция; DS-стадия опциональна (триггер — handoff или явный запрос).
- Handoff: статус кода `reference` | `foundation` — решает пользователь на гейте; строка в
  `memory/decisions.md` — последняя операция. Состав рассчитан на дизайн-деливераблы: перед
  реализацией продукта состав дополняется dev-дорожкой повторным `/qtim:setup`.
